1. The big picture (in simple words)

Two websites run from one code base. The shop (what customers see) and the admin (what the owner and staff use). Both run on Cloudflare’s network, close to the customer, and both talk to one database and two picture stores.

Shop

nureasmir.com (and www, which redirects to it). Cloudflare Worker named nure-asmir.

Admin

admin.nureasmir.com. A separate Worker named nure-asmir-admin, never indexed by search engines.

Why two?

The free Cloudflare plan allows a program of at most 3 MB (compressed). The shop and admin together were too big, so each is built separately (scripts/build-target.mjs).

3. What happens when someone opens a page

  1. The browser asks DNS for nureasmir.com. Cloudflare answers.
  2. The request reaches Cloudflare in Lahore. A small program (middleware.ts) adds security headers and redirects www and http to the one real address.
  3. The Worker looks for a saved copy of the page (regional cache, then R2). If it is fresh, it answers at once (about 0.3 s measured).
  4. If not, it builds the page from the database in Singapore and saves the copy (0.7–2.7 s measured, see document 3).
  5. Pictures come from /cdn/… with a one-year cache, so a returning visitor downloads them once.

6. Security in one paragraph

Admin sign-in is separate from the shop and rate-limited. Every price is recalculated on the server (the browser’s numbers are never trusted). Secrets live only in GitHub and Cloudflare, never in the code. Security headers (CSP, HSTS, no framing) are set on every page. Dependencies were patched this week; one low-risk advisory remains in developer-only tooling (braces, no fixed version exists yet). The Firebase browser key is now limited to our own websites.
